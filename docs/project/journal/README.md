# GML — Journal de progression

Journal des avancées du projet **GML – Swiss Voting**. Une entrée par **journée avec progrès vérifiable** (fuseau `Europe/Zurich`) : `YYYY-MM-DD.md`.

## Règles

- Ne créer **aucune entrée** pour les jours sans changement concret et vérifiable.
- Utiliser les commits, pull requests, issues et documents du dépôt comme sources ; citer les liens et identifiants des éléments utiles.
- Distinguer **travail effectué**, **décisions prises** et **raisons de ces décisions**. Ne pas déduire une motivation du seul diff : en l'absence de justification explicite, écrire « Raison non documentée ».
- Préciser les résultats, vérifications ou tests, limites et prochaines étapes quand les sources les attestent.
- Si plusieurs contributions ont lieu un même jour, **mettre à jour la même entrée** en préservant le contenu saisi manuellement et en évitant les doublons.
- Ne pas inclure de secrets, données personnelles ni résultats non étayés.
- Les journaux individuels demandés par le cours restent distincts de ce journal technique commun.

## Modèle d'entrée

```markdown
# Journal — YYYY-MM-DD

## Travaux effectués
- Description factuelle du progrès — preuve : lien vers commit/PR/issue.

## Décisions prises et raisons
- **Décision :** …
  **Pourquoi :** … (ou « Raison non documentée »)
  **Preuve :** …

## Résultats et vérifications
- …

## Difficultés / limites
- …

## Prochaines étapes
- …
```

Ce journal reflète uniquement les éléments accessibles et documentés dans le dépôt ; pour capturer les discussions hors GitHub, reporter leurs conclusions dans une issue ou une pull request.
